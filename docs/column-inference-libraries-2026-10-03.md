# Column inference libraries for Analytico

Checked 2026-10-03 against official documentation and repositories. Repository links point to moving branches; verify dependency and API details against a pinned release before adoption. This is a capability review, not an accuracy benchmark.

## Finding

There are useful open-source libraries for parsing, profiling, semantic data labels, and extensible type rules. None of the reviewed deterministic libraries gives a complete, safe answer to Analytico's question: *what is this column for, what units does it use, how may it be aggregated, and can its source values be converted without loss?* Those are separate decisions. In particular, identifiers, ordinal codes, counts, and measurements can all be represented by integers. Even a correct label such as `QUANTITY` does not establish units or prove that summing values is valid.

The nearest deterministic baseline to assess is **Visions**, for extensible logical types over pandas data; pair it with the app's existing all-value checks for any accepted conversion. **DataProfiler is a meaningful semantic-labeling challenger**, especially for known entities and its `QUANTITY`/`ORDINAL` labels, but those labels do not specify business aggregation. **Frictionless** is useful when the goal is an explicit inferred/declared data schema and validation. The other candidates solve narrower tasks.

## Recommendation before a Luna benchmark

Do not judge a hand-written heuristic against the phrase “industry standard”: the reviewed projects themselves use explicit rules, thresholds, samples, or narrow label taxonomies. The custom rule is not weak because it is custom; the question is whether its outputs are explicit, evidence-based, conservative, and measured on representative data.

For a **deterministic-only baseline**, assess Visions as an optional source of physical/logical type evidence, or retain the current implementation if its dependency and API integration costs outweigh its benefit. Its built-in ordinal behavior expects ordered categorical metadata; it does not solve integer-code discovery. Do not add YData Profiling solely to replace a few role rules: it adds a report/profiling stack and has its own tunable cardinality heuristic. DataProfiler is the most relevant library in this set for a *semantic annotation* comparison, but its labeler's categories and dependencies need separate evaluation.

For every library proposal, preserve raw source values, record the detector and evidence, allow unknown/overrides, and validate every non-null value before a cast. Store role, unit, and supported aggregations independently. A library/model may suggest those fields; only source metadata, user confirmation, or validated policy should authorize operations. Compare deterministic baseline, candidate library, and Luna on the same held-out fixtures and score incorrect confident labels and chart/aggregation safety, not just coverage.

## Source and maintenance caveat

Maintenance evidence was checked from official repositories as of the date above, not independently audited: Visions showed repository activity through 2026-05; Frictionless through 2026-07; DataProfiler's repository/issues were active in 2026-09. The public DataPrep `develop` branch and package docs were available, but this short review did not establish its release cadence. csvkit, agate, CleverCSV, and skimpy docs/source were inspected for capability; this is not a full maintenance or security audit. Recheck the selected project's tagged release, supported Python/pandas versions, license, and dependency resolution before adopting it.

## Parsing engines already solve a different layer

DuckDB's CSV sniffer detects delimiter/quoting/header and parseable column types. Type candidates are configurable, explicit overrides are supported and `all_varchar` preserves source text. Its documentation does not promise identifiers, quantitative roles, units or business aggregation inference. [Official auto detection](https://duckdb.org/docs/current/data/csv/auto_detection).

Polars similarly infers physical schema from `infer_schema_length` rows, accepts schema overrides and supports reading everything as strings. More rows improve physical inference at additional cost; this does not infer a business metric. [Official read_csv interface](https://docs.pola.rs/api/python/stable/reference/api/polars.read_csv.html).

Arrow infers primitive numeric/date/time/string types and supports explicit column types. Its incremental reader infers from the first block and freezes types afterwards, so a prefix is not a complete-file guarantee. [Official CSV docs](https://arrow.apache.org/docs/python/csv.html).

Analytico already uses DuckDB's native reader for large files with explicitly specified VARCHAR source columns and `auto_detect=false`, then validates conversions separately. That choice protects source values and permits the existing parsing/review contract. Replacing it with eager native casting is not a free semantic improvement. A library trial should produce proposals and preserve full-value/source checks before any conversion. The small-file path currently uses pandas. No additional parser is needed just to label numeric measures.

## Learned semantic classifiers exist

These are AI models running locally, not deterministic inference libraries:

- **Sherlock** exposes a pretrained semantic classifier with `predict`/`predict_proba`, 78 labels in the original model and an explicit feature extraction stage. Its README gives labels such as name and address, with statistical, character and embedding features. [Official repository](https://github.com/mitmedialab/sherlock-project).
- **Sato** adds whole-table context through topic modeling and structured predictions to Sherlock-style per-column predictions. Its project distributes research scripts and pretrained weights. [Official repository](https://github.com/megagonlabs/sato).
- **Doduo** exposes `annotate_columns` for pandas, returning semantic types, relations and embeddings. The inspected wrapper uses CPU BERT with fixed vocabularies of 78 or 255 labels, depending on model. Its checked-in requirements pin pandas 1.2.4, torch 1.8.1 and transformers 4.5.1, indicating an integration modernization requirement for our current app; this does not establish a project abandonment date. [Official repository](https://github.com/megagonlabs/doduo), [wrapper implementation](https://github.com/megagonlabs/doduo/blob/main/doduo/doduo.py), [requirements](https://github.com/megagonlabs/doduo/blob/main/requirements.txt).

Their taxonomy is not our metric/category/identifier/temporal contract. Benchmark label mappings must be specified before evaluating, and unsupported classes must stay unsupported rather than relabel every number a metric. None of these inspected interfaces specifies weighted-rate definitions or an authoritative business aggregation for arbitrary CSVs. Published scores on their own benchmarks cannot be treated as expected accuracy on our bike, bank, retail, taxi and wine files. No local CPU latency, peak memory or model bundle size has been measured here.

## Clarification of the earlier “industry standard” wording

Custom heuristics are not automatically wrong, and widely used libraries themselves use heuristics. What is established is the separation of physical schema, semantics, user definitions and chart usage. There is no single numeric-cardinality threshold common to all the inspected systems. Our previous rule was unsuitable because it changed analytical role merely when the exported rows changed and confused statistical presentation with business meaning. Our current header hints and fractional-number candidates are still custom proposals requiring evaluation; they are not a certified standard or a guarantee.

This research does not replace the current engine or run a new Luna benchmark. Library candidates should first be evaluated in an isolated environment, with physical parsing scored separately from semantic roles, plus false assignments, abstention coverage, source preservation, local CPU time and memory. Prefer a bounded proposal stage; do not materialize the full taxi table into pandas just to run a profiler.

DataProfiler also has a separate statistical categorical detector: the inspected source returns true with at most ten unique values, or a uniqueness ratio at most 0.2. That flag is distinct from the learned data label; treating it as a prohibition on numeric measurement would reproduce our earlier mistake. [Official categorical profiler implementation](https://github.com/capitalone/DataProfiler/blob/main/dataprofiler/profilers/categorical_column_profile.py).

## Follow-up: actual local benchmark

The candidates were subsequently installed and executed, alongside fifteen live GPT-6 Luna requests. See [the measured comparison](library-comparison-benchmark-2026-10-03.md) for native-label mappings, accuracy/abstention results, latency, memory and packaging constraints. The native library outputs did not resolve additional unknown analytical roles on this workload; Luna recovered more roles but still needed stronger conflict guards. These measurements supersede the unmeasured integration expectations above.
