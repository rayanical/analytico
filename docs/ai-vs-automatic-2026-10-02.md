# Automatic rules versus GPT-6 Luna interpretation

## Recommendation

Keep fast deterministic ingestion, run AI interpretation in the background, and keep Review columns optional. Luna is substantially better at identifying semantic roles on this regression set. The current prompt and runtime contract are too conservative to replace automatic parsing wholesale: uncertainty about aggregation or units blocks an otherwise valid parsing decision.

Before automatic AI application, separate decisions about parsing, semantic role, unit and aggregation. For example, recognizing EUR-prefixed numeric values should not require knowing whether the user eventually wants their sum or average. Preserve unknown units and unsupported operations; never invent metadata to avoid clarification.

The column editor no longer opens automatically after import. The parsing preview remains; this benchmark does not change production AI behavior or enable automatic model-driven mutations.

## Method

Frozen `column-interpretation-v3`, `gpt-6-luna`, reasoning none, strict structured output, cache bypassed. Sixty live requests: thirty existing holdout fixtures in each of two arms. No dataset files or credentials were sent; the requests contained synthetic fixture values and bounded context.

- **Automatic:** current `clean_dataframe(..., interpret_columns=False)`, semantic detection and profiling; five local repetitions per column for timing.
- **Luna / upload inputs:** the same fixture values and names, with context generated by the production `_interpretation_input` function: bounded profile, no requested calculation or external metadata.
- **Luna / supplied context:** the original fixture context, which may establish currency, units, requested aggregation, weighting or business meaning.

Expected labels never enter model requests; the existing runner projects only names, values and context. The holdout file has been used in earlier prompt development, so this is a regression comparison, not a newly unseen generalization test. One live prediction per fixture and arm; no repeat-stability claim. Small column fixtures measure semantic interpretation, not million-row ingestion or memory performance.

The upload-only arm is deliberately scored against the same original labels to show which contextual decisions become unavailable. Its lower full-decision score and extra clarifications are not all model errors: some fixture answers genuinely require the business context withheld in that arm.

## Results

| Measurement | Automatic | Luna / upload inputs | Luna / supplied context |
| --- | ---: | ---: | ---: |
| Column-role match | 18/30 (60%) | 29/30 (96.7%) | 30/30 (100%) |
| Parsing-policy match | Not exposed | 27/30 (90%) | 28/30 (93.3%) |
| Unit match | Not exposed | 27/30 (90%) | 30/30 (100%) |
| Complete five-field decision match | Not exposed | 13/30 (43.3%) | 27/30 (90%) |
| Median latency | ~1.1 ms local parse/profile | 985 ms per model request | 1,151 ms per model request |
| 95th percentile model latency | — | 1,400 ms | 1,731 ms |
| Provider failures | — | 0/30 | 0/30 |

Automatic aggregation recommendations were exposed for only 12/30 columns; 7/12 matched the contextual expected labels. It has no explicit unit, parsing-policy or clarification output, so those are marked unsupported rather than assigned zero accuracy. The model timing excludes local parsing; the local timing excludes any model request. The comparison establishes the order-of-magnitude latency difference, not an equal-work end-to-end file benchmark.

Both AI arms flagged all eleven contextual ambiguity cases for clarification. Upload-only inputs flagged nine additional cases relative to the contextual labels. The model made ten apparently actionable upload-only decisions; four differed from expected action fields, including categorical `none` versus requested `count` and an ordinal numeric risk band treated as an identifier. This is why passing numeric validation alone does not establish semantic correctness.

The current production background job also has a twelve-column cap and checks a twelve-second soft budget between calls. The live benchmark evaluates all thirty separately, bypassing that job orchestration; a wide upload will not receive this coverage today.

## What validation actually permits

Saved live predictions were replayed, without further provider calls, through the existing full-column interpretation guards in `data_janitor`. This simulates that existing accepted-interpretation path; it is not a claim that the current background worker applies proposals automatically or a benchmark of a future policy bridge to schema rebuilding.

| Replay | Applied | Retained for review |
| --- | ---: | ---: |
| Upload-input decisions | 10/30 | 20/30 |
| Supplied-context decisions | 16/30 | 14/30 |

The supplied-context arm improved EUR-prefixed amounts from retained text to numeric measures and recognized customer-reference codes as identifiers. The upload-only arm preserved otherwise parseable USD amounts and percentages because their requested aggregation was unknown. The guard changes uncertain roles to `unknown`, so its role-label match can fall despite correct model recognition; that is abstention, not proof of corrupted data.

Additional replay checks appended a contradictory final record after 2,000 valid records: mixed currency, invalid currency text, and a submicrosecond timestamp. All three retained the complete source values. These test runtime preservation; they are not additional live model trials or exhaustive safety guarantees.

## Usage and cost

The sixty calls reported 57,797 input tokens and 2,490 output tokens. Neither response set reported a billed cost. At the published standard text rates of $0.10/M input and $0.50/M output, the undiscounted estimate is **$0.0070 total**; this is a rate-based estimate, not a billing observation. Cached input rates or a different service tier can change actual billing. Pricing source: [official GPT-6 Luna documentation](https://developers.openai.com/api/docs/models/gpt-6-luna), checked October 2, 2026.

The adapter reported the requested model `gpt-6-luna` for both runs. No Jev requests, retries, prompt adjustments, reasoning experiments or automatic production parsing changes were made for this comparison.
